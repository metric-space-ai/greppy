# Repository command verification

All 24 registry repositories have a syntactically complete adapter config.
None is production-ready yet: every row remains `pending` until its own real,
two-repetition offline smoke ledger is generated by the adapter and bound to
the exact adapter proof and image ID. A tool-version probe alone cannot make a
row ready.

The following configs additionally need manual repository-specific command
review before (or as part of) their first smoke. Their current commands are
conservative candidates, not a claim that path selection or required services
are correct:

| Repository | Manual verification still required |
| --- | --- |
| `go-prometheus` | Confirm whether root `go test ./...` has generated UI/asset prerequisites in the offline image. |
| `go-kubernetes` | Replace or confirm the root-wide Go invocation with the repository-supported package runner. |
| `typescript-zod` | Confirm the pnpm test script forwards changed test paths for the frozen revision. |
| `typescript-vite` | Confirm workspace/package selection and changed-path forwarding. |
| `typescript-compiler` | Replace generic `npm test` arguments with the supported `hereby`/compiler-suite selector. |
| `java-kafka` | Confirm module-scoped Gradle tasks and any Scala test filtering required by changed paths. |
| `cpp-opencv` | Confirm module selection, external data requirements, and usable CTest labels in the offline image. |
| `javascript-eslint` | Confirm npm's test script forwards individual changed test paths. |
| `javascript-webpack` | Confirm the frozen revision's package manager and test-path selector. |
| `javascript-node` | Confirm `tools/test.py` path syntax and the smallest valid PASS_TO_PASS suite after rebuilding. |
| `ruby-rails` | Confirm component-specific Rails test runner and offline database requirements. |
| `ruby-discourse` | Confirm service-backed RSpec setup (database/Redis) inside the isolated validation image. |

The remaining repositories use conventional repository-native commands
(pytest, Cargo workspace tests, Go tests, Maven/Gradle full tests, CMake+CTest,
or RSpec). Those commands are still only *candidates* until the same real smoke
gate passes; this document does not whitelist them.

For CMake and native Node changes, `post_patch_commands` rebuild after the
hidden test or full gold patch is applied. This prevents CTest or Node's test
runner from accidentally exercising stale binaries.
