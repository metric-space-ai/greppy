# 0.4.0 release readiness — 2026-09-04

Status: **not approved for release**. This is an implementation/evidence ledger,
not a substitute for the immutable-SHA release gates.

## Implemented in this stabilization change

- Separate private agent browser runtime roots (`GREPPY_WEB_RUNTIME_DIR`) from
  shared inference roots and model-owner locks. Explicit whole-runtime harness
  isolation via `GREPPY_RUNTIME_DIR` remains supported.
- Existing private daemon endpoints can be resolved from a write-confined
  client without chmod. Two subprocesses with different browser roots contend
  for the same model lock; the sandboxed-client regression passes on macOS.
- Resolve launcher symlinks before locating the bundled Web runtime; preserve
  explicit runtime overrides and existing rejection of symlinked dist members.
- Retain private startup stderr on failure; identify the selected executable,
  child exit status/readiness deadline, and log path in the error.
- Correct browser instructions: `session create`, `script save --file`,
  `dom html`; do not equate successful dispatch with verified DOM state.
- Signed app gains read-only `--fskit-status` using Apple's public FSClient API.
  Setup requires the native module to be enabled at the exact bundle path,
  rather than trusting pluginkit election alone. Old apps without the helper
  are identified as a mismatched bundle, not repeatedly sent to the toggle.

These tests do not constitute a real 10-/50-agent GPU/RAM test or a successful
FSKit-backed model run. Real-device acceptance of the new signed helper is pending.

## Current machine evidence

- Installed app was not replaced. Its signature verifies. The CLI copy was
  replaced atomically with a link to that same signed app's CLI; the old copy
  is recoverable under `~/.local/bin/.greppy-install-backup.BS1xMn/greppy`.
  This alone does not fix the old CLI's symlink-resolution behavior. The old
  sibling Web runtime remains untouched because other tasks had live processes.
- pluginkit reports the exact installed extension as elected (+), version 0.4.0.
  Actual mount reports the module disabled; no provider process/mount is active.
- A standalone public-FSClient query enumerates Apple's exfat/msdos/ftp modules
  but no Greppy module. The signed host's equivalent query still needs the new
  notarized bundle. No claim that another toggle or reboot alone fixes this.
- Sampling the old orphan Web controller reached V8 FatalProcessOutOfMemory
  during isolate initialization. This does not explain the separate CI Content
  worker handshake timeout, and is not evidence of slow webpage loading.
- The browser-comparison task verified initial TodoMVC actions using the current
  matching App CLI/runtime and a private test runtime. Normal PATH startup is
  not yet accepted. No unrelated worker was killed.

## Open gates / investigations

1. Signed updated App/CLI package, real FSKit mount, fresh mounted heartbeat
   over 60 seconds, .git operations, two consecutive agents, upgrade/login/reboot.
2. True 10-/50-agent inference acceptance: one owner per model/device, load and
   offload behavior, fairness, memory growth, client cancellation vs shared jobs.
3. Explain the same-SHA Web CI Content-worker startup timeout; three repeatable
   complete suites with no unexplained failures. CLI logs are better, but the
   underlying runtime startup issue is not declared fixed.
4. New browser-comparison findings need minimal independent reproductions:
   primitive CLI -> pw loses the current page; exact text can match extra nodes;
   TodoMVC editing through fill/Enter does not save; possible session isolation.
   Do not broadly modify React, selectors, or timeouts from these reports.
5. CTOX qualified who-calls report remains open. The live retry was blocked by
   a changed HEAD/index signature in that active checkout; no broad reindex or
   source mutation of CTOX was performed.
6. Windows Microsoft-signed private driver, catalog and bound contract are
   absent from repository secrets. Microsoft Hardware Developer Program access
   / responsible account owner is required; scope remains three platforms.
7. Exact final SHA: all CI/security/model-provenance/task-bank/summary gates,
   real three-platform CoW performance, signed dry-run and clean installer
   installation/upgrade/uninstall. Intermediate green runs do not transfer.

No final RC has been frozen, no main integration performed, and no v0.4.0 tag
or release authorized by this change.
