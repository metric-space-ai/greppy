# 0.4.0 release readiness — 2026-09-05

Status: **not approved for release**. This is an implementation/evidence ledger,
not a substitute for the immutable-SHA release gates.

## Implemented in this stabilization change

- Separate private agent browser runtime roots (`GREPPY_WEB_RUNTIME_DIR`) from
  shared inference roots and model-owner locks. Explicit whole-runtime harness
  isolation via `GREPPY_RUNTIME_DIR` remains supported.
- Existing private daemon endpoints can be resolved from a write-confined
  client without chmod. Two subprocesses with different browser roots contend
  for the same model lock; the sandboxed-client regression passes on macOS.
- Resolve launcher symlinks before locating the bundled Web runtime; preserve
  explicit runtime overrides and existing rejection of symlinked dist members.
- Retain private startup stderr on failure; identify the selected executable,
  child exit status/readiness deadline, and log path in the error.
- Correct browser instructions: `session create`, `script save --file`,
  `dom html`; do not equate successful dispatch with verified DOM state.
- Signed app gains read-only `--fskit-status` using Apple's public FSClient API.
  Setup requires the native module to be enabled at the exact bundle path,
  rather than trusting pluginkit election alone. Old apps without the helper
  are identified as a mismatched bundle, not repeatedly sent to the toggle.

## Subsequent bash-smart defect correction

When the index writer owns the store, long command output previously fell back
to the complete original log after its verdict/diagnostics. This contradicted
the compact-output contract and duplicated diagnostic blocks. Folding now stays
active without an expansion pack: it points to the already retained raw spool
file instead of inventing an expand ID. Short output and child exit status are
unchanged. If a raw recovery path is unavailable, full output remains the safe
fallback.

Regression: hold a real index writer, execute a command producing 500 stdout and
500 stderr lines, assert compact delivery for both, and verify both retained
raw files byte-for-byte. All 11 bash-smart integration tests and 22 unit tests
pass, plus library Clippy and formatting. No CTOX files or jobs were changed.
This subsequent product change requires new exact-SHA gates; the earlier signed
bundle is diagnostic evidence only, not a final artifact for the new source.

## Rust `raw` identifier false syntax rejection

The reported valid Rust module was independently minimized to
`fn main() { let raw = 1; let _ = &raw; }`. Rustc (edition 2021) accepts it;
the installed CLI and the preceding release build both refuse `write --dry-run`
with exit 13. Tree-sitter Rust 0.23.3 marks `&raw` as ERROR. The reported
80-line module has that same single error at line 74, not in its let-else,
JSON macro or query closure. This matches the upstream grammar report
<https://github.com/tree-sitter/tree-sitter-rust/issues/277>.

Upgrade only the Rust grammar dependency to 0.24.2. The minimal regression
changes from red to green, and the full original module now passes the actual
CLI dry-run in an isolated directory. Tests cover `&raw`, slicing/indexing,
genuine `&raw const`/`&raw mut`, let-else and macro/closure forms. The CLI test
checks dry-run, actual byte-exact creation, and rejection of malformed Rust
without overwriting the previous file. Rust edit-grid tests remain 16/16;
CLI edit-family is 13/13, prompt contract 19/19, Store-CoW 3/3 (performance
gate not run). Parser 211/211, indexer 66/66 and edit library 85/85 pass;
formatting and CI-policy Clippy also pass. The generic rejection's missing source location remains a
separate diagnostics improvement, not a reason to disable syntax checking.

Indexer identity advances to v5 because existing Rust extraction trees may
have been incomplete. Old stores therefore require freshness reconciliation;
this is not a claim of zero upgrade indexing cost or a new embedding-cache
policy. No CTOX source or installed package was changed. As temporary recovery
on the old binary, `&(raw)` passes the independently tested dry-run.

## Standard Git multi-file patch boundaries

The reported unchanged Git diff for 475b8152 failed because the hunk reader
treated the next `diff --git` envelope as unprefixed hunk content. This is a
functional multi-file parser defect, not invalid caller syntax. The parser now
ends a hunk/file at that envelope and accepts its optional `index` metadata.
Prefixed source lines containing those words remain source, not metadata.
Unsupported binary, rename, mode-only or truncated Git sections fail explicitly
before applying anything; they are never silently omitted from a transaction.
Existing-file-only, context anchoring and all-files-or-nothing rules remain.

Three regressions fail before the correction and pass afterward. The complete
edit-family suite passes 16/16. The exact reporter patch was applied unchanged
to five isolated files extracted from 475b8152's parent: dry-run and execution
both exit 0, and all five resulting Git blob hashes exactly match 475b8152.
The reporter's checkout and patch were read-only. This correction is developed
on codex/patch-git-metadata so the in-flight 94d16c0b release gates retain their
exact subject; those earlier gates do not cover this subsequent product fix.
